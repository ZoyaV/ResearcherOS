Git synchronization

koi-project-sync

At session start and after experiments

Pull and push research materials without committing secrets or platform code.

What it does

Synchronizes only research materials: reports, the board, the hypothesis tree, and findings. It pulls repository changes first, then saves and pushes local edits when needed. Secrets and ResearcherOS platform code are excluded from commits.

Why use it

Give the team one current view of the research so results do not remain local or overwrite other people's updates.

When to use it

  • Pull the latest materials at the beginning of a session
  • Share a completed experiment or new report
  • Handle the Sync button or an explicit synchronization request

How to invoke it

Ask the AI assistant to synchronize a specific project, or click Sync in ResearcherOS. The workflow can use the deferred-push queue and local-changes status.

Example request for the AI assistant in your editor:

Synchronize project my-project with its repository:
pull changes first, then push local research-material edits if there are any.

Workflow diagram

Every session starts with a pull, followed by a check for local changes. Changes are committed and pushed; otherwise the workflow waits and checks again later.

flowchart LR
  A[Session starts] --> B[Pull changes]
  B --> C{Local changes?}
  C -->|yes| D[Commit research materials]
  D --> E[Push to repository]
  C -->|no| F[Wait]
  F -->|after 30 minutes| B
