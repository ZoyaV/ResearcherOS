Card execution

koi-execute-card

Execute the card or run an experiment

Have the AI assistant run a card's experiment from in progress to report, finding, and done.

What it does

The assistant owns the card end to end: moves it to in progress, performs the experiment described by report subtasks (code, runs, metrics, and artifacts), checks off work, records results, reviews the report, moves the card to done, formulates a finding, and synchronizes when needed. It can maintain a live-progress note. Use autoresearch for multi-hour runs with separate roles.

Why use it

Make card execution mean a complete experiment while keeping the board, report, and facts aligned.

When to use it

  • A request requires a real run rather than advice
  • A short experiment the assistant can run and measure
  • A long remote run where autoresearch adds roles
  • An in-progress card still needs its subtasks and report completed

How to invoke it

Name the project and card, and ask for complete execution: in progress, every experiment subtask, done, and a recorded finding. Ask for autoresearch when a long run needs roles.

Example request for the AI assistant in your editor:

Execute card <title or id> in project <project> end to end:
move it to in progress, run every experiment subtask, update progress, and finish with done status and a finding.

Workflow diagram

Moving to in progress is followed by actual subtask execution, results, report review, done status, a finding, and synchronization. Autoresearch roles fit inside the execution step.

flowchart TD
  A[Find card] --> B[Move to in progress]
  B --> C[Read specification and subtasks]
  C --> D[Run experiment subtasks]
  D --> E[Check off completed work]
  E --> F[Record results]
  F --> G[Review report]
  G --> H[Move to done]
  H --> I[Formulate finding]
  I --> J[Synchronize]
