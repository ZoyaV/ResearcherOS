Repository onboarding

koi-project-onboard

You have code but no research materials

Connect an existing code repository to ResearcherOS and build a research tree.

What it does

Connects an existing experiment repository to ResearcherOS. The AI assistant reviews the code and related literature, leads a layered discussion (problem → program → causes and hypotheses → methods), checks that node titles make sense to an outside reader, writes the research files beside the code, and can place them on a separate branch so the code branch remains clean.

Why use it

Avoid rebuilding a hypothesis tree manually when code already exists, while keeping research materials separate from code.

When to use it

  • A code repository has no research-materials directory yet
  • You want to formulate the problem and hypotheses using the code and literature
  • The team wants research materials on a separate branch

How to invoke it

Open an AI-assistant chat in a workspace containing ResearcherOS and your repository. Ask it to connect the project path and follow this workflow through to completion, including a separate branch for research materials.

Example request for the AI assistant in your editor:

Connect /path/to/my_experiment to ResearcherOS.

Follow the onboarding workflow through to completion: build the hypothesis tree and save the research materials on a separate repository branch.

Workflow diagram

Environment checks and code review come first, followed by a literature check and four layers of conversation. Titles are then checked for clarity and style. Only after that are files written and, if needed, a separate branch created. An existing tree is never overwritten.

flowchart TD
  A[Check environment and review code] --> B[Review literature]
  B --> C[Discuss the problem]
  C --> D[Discuss the program]
  D --> E[Discuss causes and hypotheses]
  E --> F[Discuss methods]
  F --> G[Check title clarity]
  G --> H[Check writing style]
  H --> I[Write the research tree]
  I --> J[Create a separate repository branch]
