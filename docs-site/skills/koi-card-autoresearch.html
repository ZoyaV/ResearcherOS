Card autoresearch

koi-card-autoresearch

Systematic research or a multi-hour run

Run one card over a long period with Manager, Researcher, and Debugger roles.

What it does

The Manager moves the card to in progress and configures the live window and state file. The Researcher starts and monitors the job and checks off subtasks. The Debugger only diagnoses failures and records recommendations; code changes and restarts remain the Researcher's responsibility. Kanban, reporting, and done status follow card execution.

Why use it

Keep multi-hour or remote runs from becoming start-and-forget jobs by separating operation, monitoring, and diagnosis.

When to use it

  • A request for systematic research or autoresearch
  • A job lasting hours or days that needs monitoring and failure triage
  • A project launch skill needs a shared role protocol

How to invoke it

Ask for autoresearch and provide the project plus card ID or title. Mention any project-specific launch skill. Roles and cadence come from this workflow; kanban handling comes from card execution.

Example request for the AI assistant in your editor:

Run systematic research for card <id> in project <project>:
use Manager → Researcher → Debugger roles and monitor progress throughout.

Workflow diagram

The Manager acts once at the beginning. Researcher and Debugger then operate in parallel: the Researcher checks job health frequently, while the Debugger performs scheduled and incident triage. The workflow ends with a report and done status.

flowchart TD
  U[User request] --> M[Manager: in progress + live view + state]
  M --> R[Researcher: start job]
  R --> W[Watch: every minute × 20, then every 20 min]
  R --> D[Debugger: every 10 min]
  W -->|failure| I[Call debugger]
  I --> D
  D -->|recommendation in state| W
  W -->|complete| F[Report + done + finding]
